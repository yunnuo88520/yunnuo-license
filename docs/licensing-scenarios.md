## 历史场景说明（V1）

# 标准产品授权与更新

开发者维护一个应用、一个 AppID 和版本库，接入一次后统一编译和分发。不同客户购买不同套餐，在产品安装向导输入自己的卡密并登记部署信息；不为每个客户生成源码或专属二进制。公开 config.json 不包含客户卡密、安装凭证和 AppSecret。

## 管理流程

1. 创建应用，系统生成 AppID。为应用配置“默认授权条款”，或在“套餐与结算”创建独立规格。一个应用可同时销售域名版、设备版、集群版等套餐。
2. 套餐创建时冻结条款，发卡保存套餐快照，激活后保留授权快照。更改默认值影响之后按默认规则发卡的业务，不回写已有套餐、库存卡和客户授权。需要修改售价可调整成本，需要修改规格则建立新套餐。
3. 管理员向代理授予可售套餐；管理员、代理或所属开发者选择套餐发卡。期限、配额、功能和代理成本都有明确来源，客户端不决定购买权益。
4. 客户安装统一产品，激活卡密。产品先调用 cards/requirements 读取本卡规则，再创建私有安装身份和实际绑定。产品必须在核心业务入口核验 can_use。
5. 产品生成十分钟一次性关联凭证，客户在用户中心关联，之后可查看授权、实例、续费和按冻结的换绑规则操作。已有所有者的授权不能被其他账号认领。
6. 需要更新时启用应用升级服务，上传、发布适用于各平台的版本。检查、下载、下载后与实际安装前都验证当前更新资格。

## 产品形态

| 形态 | 推荐标识与持久化 | 更新方式 |
| --- | --- | --- |
| Web、私有化网站 | 实际请求 Host、部署实例；私有状态放静态目录之外 | 签名归档、备份数据库、文件切换、健康检查与回滚 |
| Docker、Compose | 命名卷保存实例与授权；不能使用容器 ID 或临时 IP | 签名 docker save 压缩归档、固定镜像 ID、替换容器、保留卷 |
| 集群、Kubernetes | 稳定集群 ID；各副本独立实例、共享配额或浮动席位 | 控制器执行滚动更新；平台提供资格和签名文件 |
| GUI、CLI、后台服务 | 设备提供器、安装实例、进程席位 | 平台匹配安装器或归档；原生 GUI 示例会实际替换产品核心程序并回滚 |
| 插件、移动应用、IoT | 宿主实例、产品账号、设备或组合条件 | 共用授权协议；安装方式遵循宿主或应用商店规则 |
| SaaS | 产品自己的组织／租户 ID 或账号 | 一般由开发者集中升级，按租户验证功能及使用资格 |

forms 是产品交付说明，不会让一个通用安装器自动适配所有平台。已实跑 Linux Web、CLI、Tk GUI 和 Docker；Android/iOS、具体插件宿主、Kubernetes 控制器需要开发者在对应产品接入同一协议。后端原生发行包为 Linux amd64/arm64。

## 绑定与数量

| 方式 | 激活登记 | 在线校验 |
| --- | --- | --- |
| domain | app.example.com | 实际请求 Host；不能使用配置中的固定域名替代真实访问 |
| domain_wildcard | *.example.com | 实际子域。默认仅一级、不含根域；可显式开放所有层级或根域 |
| ip | IPv4 或 IPv6 | 产品的实际部署 IP |
| ip_cidr | 规范 CIDR，例如 192.0.2.0/24 | 网段中的具体部署 IP，支持 IPv4/IPv6 |
| device | 稳定设备标识 | 产品设备提供器获取的同一标识 |
| instance | 本安装随机 ID | 相同 ID 与私有凭证 |
| account、tenant、cluster | 产品认可的账号、租户或集群 ID | 同一业务身份；tenant/cluster 保留大小写 |
| composite | 规定的各维度 JSON 对象 | 所有规定维度共同匹配；域名/IP 范围仍检查实际值 |
| none | 无部署绑定 | 仍检查授权期限、状态；可要求私有实例凭证 |

域名转 IDNA 后匹配；泛域不能注册公共或托管后缀，如 *.com、*.co.uk、*.github.io。根域和 www 可按两个精确绑定出售，或显式采用包含根域的泛域规则，二者范围不同。

绑定规则数量、安装实例数、设备数、并发席位是不同额度。例如一个泛域规则可以允许三个安装，但只允许两个进程同时使用。要求安装身份时，所有请求带 instance_id / instance_secret；实例 ID 为 16–64 位小写字母、数字、下划线或连字符，凭证为随机 32 字节十六进制。重启、容器重建保留该身份，不重复消耗安装数；丢失私有状态需按换绑策略恢复。

设备 API 接受产品提供的稳定机器标识。示例缺省生成的设备 ID 表示持久安装设备，**不是硬件防克隆指纹**；需要硬件绑定时，应提供可信的 deviceId / device_id 获取器，并处理硬件维修。复制整个私有目录也会复制身份，纯客户端机制不能保证识别所有克隆或阻止已被破解的程序。平台不提供 DNS 域名所有权证明；域名登记与所有权核验属于不同问题。

IP 是受保护产品的部署地址，不是任意访客 IP。当前协议允许产品声明部署 IP，因此产品需从可信网卡、云元数据或部署控制器获取，不能把浏览器参数、任意转发头当作证据。授权 API 另有可信代理设置，用于限流和风控的来源 IP。

## 席位与离线

每个进程生成独立 session_id，通过 seats/acquire 获取 seat_id。并发检查与分配在同一授权行锁中执行；跨进程复用席位、超额申请被拒绝。在线程序定期续租，退出 release；异常退出由租约到期回收。

显式借用席位时，借用天数不能超过套餐离线上限和使用宽限截止。签名借用凭证绑定产品、授权、安装、进程、席位和具体绑定值；借出后仍占用额度，提前 release 或停用实例不会提前腾出这份额度。普通在线席位的缓存不能代替离线借用。

默认严格在线。Node RuntimeLicense 可选择不超过 60 秒的正向缓存，并在使用、席位和更新截止裁剪；离线容错必须启用持久时间高水位守卫。明确的 4xx 拒绝、坏签名和存储错误不能触发离线放行。Go/Java 提供验证工具，由产品明确安排缓存与离线策略。

完全离线文件按设备单独签发，客户端可导入、重复验签，验证产品、签名、公钥版本、设备和期限。离线文件不授予在线更新资格。断网时无法立即收到吊销或安全处置；有效期与借用上限决定这一延迟，不能承诺断网实时撤销。

## 期限和续费

- can_use 控制受保护业务；can_update 控制检查、下载及安装前授权。
- 订阅到期后可选使用宽限，宽限结束拒绝业务。宽限不延长更新资格。
- 永久使用、限期更新的授权，更新到期仍能运行已安装版本，但不能获取或新装升级。
- 更新截止恰好到达即拒绝，没有“今天到期还能多更新一天”。服务端以 UTC 时间为准，页面按用户界面时区展示。
- 常规续费、仅续使用、仅续更新三类卡分别处理；仅续费卡不能激活为新授权。续费延长对应期限，不能用新卡配额覆盖原授权的功能与数量。
- 吊销、应用停用、安全处置、绑定或实例错误仍可拒绝请求；只禁更新的处置不应禁用永久使用客户的原版。

## 多平台版本与安装

target 包含 os、arch、runtime、channel、kind，可指定来源版本 min_version/max_version。一个公开版本号可有多个目标文件；客户端提交自己的目标和当前版本。签名覆盖完整目标和升级路径，三个 SDK 下载时也检查目标、产品、大小和 SHA-256。

kind 支持 archive、installer、container_archive。Docker 归档必须带 image_tag 和不可变 sha256 镜像 ID；示例只接受产品配置仓库中的一个镜像，核对加载后的镜像 ID。这里提供镜像归档交付，不是私有 OCI registry。

下载成功后仍需保存本地待安装状态，真正改文件或切容器前重新 authorize。若此时更新资格到期、授权吊销、版本下架或更新服务关闭，应中止。执行备份、程序或镜像切换、迁移、健康检查，失败恢复旧程序和数据。实例身份、卡密状态、客户配置和数据保存在升级目录之外。

在线资格复验不能让已经被破解的客户端服从控制，也不能阻止客户手工复制一份已持有文件。应用自身仍需保护核心检查、可信公钥和升级执行器。

## 自动验证

```bash
go -C backend test ./...
go -C backend test -race ./internal/service ./internal/httpapi ./internal/store ./internal/maintenance
go -C examples/universal-client build -o /tmp/product-client .
python3 examples/platform-e2e/test_scenarios.py --server /tmp/yunnuo-server --client /tmp/product-client --screenshots --artifacts /tmp/scenarios/browser
/usr/bin/python3 examples/platform-e2e/test_scenarios.py --server /tmp/yunnuo-server --client /tmp/product-client --gui --artifacts /tmp/scenarios/gui
python3 examples/platform-e2e/test_scenarios.py --server /tmp/yunnuo-server --client /tmp/product-client --docker --artifacts /tmp/scenarios/docker
```

GUI 使用 Tk、Pillow 和 Xvfb，浏览器截图使用 Playwright 和 Chromium。测试创建隔离数据库与客户数据，Docker 只清理测试创建的容器、镜像与卷；不会接触运营库。docker/test-image.sh 另在内置 MySQL 上验证协议、并发席位与产品隔离。报告和截图由 CI 保留为 artifacts，失败时保留诊断。

数据库新增 025 迁移；启动自动迁移，升级前备份。旧规则按兼容模式读取，新配置写快照，不重写旧授权，也不回改已发布迁移文件。
