# 授权核心重构契约

V2 核心及页面已经切换。协议、实库、真实客户端、浏览器和部署验收由当前 CI 执行，结果以对应提交的报告为准；旧授权流程不是本版验收证据。

## 产品与授权

一个 Application 是一个独立策略、签名和数据范围，同一 AppID 可同时交付 Web、Docker、GUI、CLI、服务、插件、移动端、IoT 和 SaaS。开发者集成一次，客户使用相同发行包。卡密是应用内某个套餐的兑换凭证；不是某种语言或部署形态专属，也不是跨应用通用凭证。

授权模型与部署形式分别配置。套餐规定使用期限、更新期限、节点/席位/用量、允许的绑定、功能和换绑。浮动是分配方式，仍可有订阅期限；按量动作需要服务端原子扣量，不能由离线 JWT 中的计数决定。永久使用不等于永久更新。

平台账号、会话、代理身份、充值余额和站点配置属于平台范围。所有授权、销售订单、套餐、卡密、激活、绑定规则、签名密钥、用量、更新版本与应用审计数据必须携带 application_id。平台数据不伪装成某个客户应用的数据。

## 强制数据隔离

业务服务只接收应用范围仓储，不持有 sql.DB、任意 SQL 执行器或可选 application_id 参数。应用范围来自已验证的会话权限，或绑定当前 AppID 的运行时凭证。不存在“省略 application_id 表示全平台”的行为。

仓储的 select/update/delete 自动插入范围条件，insert 自动注入范围键；范围缺失或上下文与仓储不一致直接拒绝。子记录采用 (application_id, id) 唯一键和复合外键，防止把应用 A 的激活、卡密、订单等关联到应用 B 的许可证。跨应用汇总只有独立的平台管理入口可以执行。架构测试禁止新业务模块引入 SQL 依赖或获取底层数据库句柄。

Application 包含公开 app_id、独立 app_secret_hash、独立签名密钥及轮换记录、开发者归属、allowed_models、allowed_bindings、verify_policy。AppSecret 只在创建/重置时展示一次。

核心应用范围数据：

- Plan：销售模型、允许的绑定、交付形态、期限、数量、功能、费用规格；发售后由 License 保存快照。
- License：plan_id、customer_ref、active/suspended/revoked/expired、使用和更新截止、节点/席位/用量约束，以及预录的绑定哈希。
- Activation：许可证、安装公钥、归一化绑定哈希、租约截止、停用时间和可追溯的更换记录。
- CardKey：key_hash、plan_id、unused/used/revoked、bound_license_id。服务端不保存可恢复原文。
- BindingRule：应用的域名模式、CIDR 与启用状态。域名/IP 是否要求应用白名单明确配置，页面显示当前行为。
- Order/WebhookReceipt：应用内订单、渠道事件唯一键、请求内容摘要、处理结果、关联授权，重复通知不重复签发或扣款。
- UsageReceipt：扣量请求的幂等键、单位、期间和结果；在许可证行锁内执行。
- Release：平台/架构/运行时/渠道/升级路径、归档或镜像身份、文件哈希及发布状态。
- AuditEvent：应用内追加事件、原因码、脱敏数据、前序摘要与认证摘要；变更与成功审计在同一事务提交。

历史数据保留为只读档案并提供页面盘点报告，不静默清库、不猜测转换旧策略。上线前在新应用内核对客户剩余权益后重新签发；账号、代理余额和等级继续使用。旧的卡密密文不再作为导出或恢复卡密的来源。旧 API 下线和新界面切换必须配套，不能保留绕过新规则的生产写入口。

## 凭证分工

1. AppID、公钥与 JWKS 地址公开分发。
2. AppSecret 只用于开发者自己的可信服务端，不进入客户安装的 Web、Docker、GUI、插件或移动产品。服务器通过哈希验证凭证；不能从哈希恢复 AppSecret 做 HMAC。
3. 每份客户安装生成并持久保存自己的 Ed25519 私钥，平台仅保存安装公钥。运行请求签名覆盖方法、路径、AppID、规范化请求体摘要、时间戳和 nonce，检查时间窗口并在应用范围内拒绝 nonce 重放。
4. 外部销售回调使用独立渠道验签密钥，不能与 AppSecret 或安装凭证混用。页面配置通用签名回调和密钥轮换；专有支付供应商需显式适配其签名协议。
5. 许可证采用标准三段式 RS256 JWT。严格验证 alg、kid、iss、aud、exp、token_use 和绑定哈希，不要求安装本平台自定义 SDK。
6. 私钥明文仅在签名操作内存中使用。持久化时由站点主密钥加密，主密钥保存在私有服务配置中；提供密钥存储接口，不能把未接入的 KMS 宣称为已支持。

签名能证明请求使用某份安装私钥，不能证明软件实际运行的域名或物理位置。域名/IP 由应用白名单、许可证绑定、客户证明或管理员批准的安装关联共同约束；不得以用户可伪造的 Host 或任意代理头作为唯一证明。

## JWT、刷新与离线

license_token 是短期使用凭证，aud 为本应用 AppID，sub 为许可证，带安装、绑定摘要、功能和截止信息。默认刷新周期与 JWT TTL 分别配置，刷新周期不能大于 TTL。标准库始终检查 exp。

offline_token 是独立用途的签名凭证，exp 表示离线截止，包含 refresh_after 和 grace_until。网络故障才可进入明确允许的离线策略；拒绝、暂停、吊销、错误绑定、错误签名和凭证损坏不能触发离线回退。离线截止不得超过订阅使用宽限或已借出的席位截止。

JWT 不保存实时 used_seats。在线席位是签出、续租、释放、超时回收的服务端租约。离线借用在截止前持续占用配额。按量扣费动作必须在线完成幂等扣量；不靠可修改的本地计数放行。

应用独立提供 JWKS，kid 与应用/版本绑定，旧公钥按策略保留重叠期。轮换不能影响其他应用；旧升级版本的当前分发清单可以重新由当前密钥签名，包本身保持不可覆盖。

## 销售与激活闭环

管理员确认人工收款或收到已验签的销售事件后，在同一应用事务中创建订单、License 和可选 CardKey。回调事件幂等，金额、套餐、数量和客户归属由服务端验证。保留人工收款，不假定已有第三方商户配置。

卡密批量生成时一次性返回原文供本次下载，刷新后不能重新导出原文；遗失时撤销未用卡或签发新安装凭证。已使用卡关联已有许可证，重复激活只允许政策规定的原安装恢复或额外额度。

预录域名/IP 不强制客户输入卡密，但也不能只凭公开 AppID 和域名领取他人授权。通过客户登录后的安装授权、一次性安装邀请、域名控制证明或管理员批准，把预录许可证关联到本次安装公钥。内网/私网场景提供人工批准，不能为了自动探测绕过出站访问限制。

客户可将产品内激活的授权通过一次性关联凭证纳入用户中心，查看授权、续费、申请换绑、停用旧安装；已有所有者不能被覆盖。代理只能销售已授予的应用与套餐，保留等级价格、余额与事务流水。

## 运行形态

| 产品形态 | 接入锚点与生命周期 |
| --- | --- |
| GUI/裸机/后台任务 | 产品设备提供器计算机器指纹摘要；换硬件走换绑，不能把随机安装 ID 宣称为硬件指纹 |
| Web/B/S | 域名或 IP 绑定加独立安装签名；根域与 www 可作为一个站点的精确别名集合管理，不要求开放全部子域 |
| Docker/Compose | 推荐短期浮动租约；或宿主机标识与强制持久卷，不能默认取容器 MAC、hostname、machine-id |
| Kubernetes | 集群标识、节点/副本与席位分别计量；调度重建不等于硬件更换，按控制器提供的持久身份接入 |
| 插件/移动/IoT/SaaS | 宿主、设备、账号或租户由产品适配器提供；应用商店分发与许可权益分别处理 |

同一应用可提供多种套餐和部署方式。卡密对应的权益保持一致，实际安装锚点由其套餐允许范围决定，不是任意更换类型或无限复制。更新安装始终保留客户配置、持久卷和私有安装身份。

## 页面闭环

应用向导 → 模型/绑定/验证策略 → 套餐 → 人工订单/渠道回调 → 许可证或批量卡密 → 安装邀请/域名IP预录 → 激活与换绑 → 授权与更新诊断。

应用工作区提供概览、策略、套餐、销售与卡密、授权/激活、域名IP规则、版本、接入代码、审计与诊断。管理员可跨应用管理，开发者仅所属应用，代理仅授予套餐，客户仅自己授权。浅色/深色/系统主题与手机/PC 都要验证。

接入页按应用和所选语言生成依赖安装、固定公钥/JWKS、activate、verify、JWT 本地验签、错误分支和安装签名代码。首批 Go、Java、Python、Rust、TypeScript；同时提供 OpenAPI、JSON 示例和 curl，其他语言遵循相同协议，无自定义 SDK 前置条件。

## 验收门槛

- 数据访问漏传范围失败；应用 A 的所有对象 ID、kid、卡密、回调事件、nonce、用量幂等键不能操作应用 B。
- 一个标准包、多个客户、同一 AppID；卡密与预录域名/IP 两种路径都能从页面完成。
- 全模型的到期前、恰好到期、宽限截止、暂停、吊销、恢复、套餐变更、续费与更新到期分别验证。
- 多实例并发席位不超卖，崩溃超时回收、释放、借用与重放；并发扣量不超额且幂等。
- 五种语言运行生成的样例，解析真实标准 JWT/JWKS，错误 audience、kid、签名、指纹和过期均拒绝。
- 回调验签、重复事件、冲突重放、错误套餐/金额/应用/账号均验证；人工收款流程仍可用。
- 策略和白名单变更立即影响在线 verify，显式拒绝清除缓存，网络失败只在签名允许窗口离线。
- 域名别名、泛域、IPv4/IPv6/CIDR、Docker 重建、GUI 重装、多形态产品和可信代理边界实测。
- 签名更新、跨平台匹配、检查/下载/安装间到期、下架、数据保留、健康失败回滚。
- SQLite/MySQL 迁移、事务和并发；传统/Compose 部署；真实 PC/手机/桌面截图，最终 dev 与 main 的同提交完整 CI 通过后更新本地。
