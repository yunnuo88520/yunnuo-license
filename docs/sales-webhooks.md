# 销售回调与卡密交付

在应用的销售渠道页创建独立 HMAC 渠道，密钥仅当次返回，保存到你自己控制的销售服务器。客户端产品不携带渠道密钥或 AppSecret。

回调为 `POST /v2/sales/{app_id}/{channel_id}`。`X-YN-Timestamp` 为 Unix 秒，`X-YN-Signature` 为 HMAC-SHA256 的小写十六进制摘要，签名内容为 `timestamp + "\n" + 实际发送的原始 JSON 请求体`，不要在签名后重新格式化 JSON。完整 JSON 样例可在接入页“销售回调”查看，也包含在下载包 `SALES.md` 中。服务器校验时间窗口、渠道、事件 ID、套餐、金额和数量；相同事件不重复签发，篡改同事件的业务内容会拒绝。退款事件撤销原订单许可证。

页面生成卡密只当次返回，服务器只保留摘要。如果销售系统需要安全重试及可靠交付，先在自己的受控订单系统生成并保存随机卡密，再提交 `card_sha256` 数组（去除首尾空白后转大写，再计算 SHA-256；保留内部字符和横线），授权站只接收摘要。相同事件重试不需要授权站恢复原文，销售系统仍可给客户交付自己已保存的卡密。只允许受信任渠道提交卡密摘要；确保足够随机性和安全存储。

这是通用签名回调，FastSpring/WooCommerce 等需由适配器验证其供应商签名后转换。系统保留人工收款：未确认订单不产生有效授权，管理员确认后才签发。不要将“收到请求”当作“支付成功”。
