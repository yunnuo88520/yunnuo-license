# V1 历史数据与 V2 切换

当前项目尚未正式上线，本次重构采用明确切换：新建应用走 V2，旧授权数据保留只读档案，不在后台猜测旧的共享实例、组合绑定、永久授权和更新天数应该如何转换。

升级前通过“运行与容量”创建并下载加密全量备份，备份数据库、站点主密钥、私有运行配置和版本文件。先在隔离副本验收，确认能恢复，再更新程序与前端。

程序启动执行增量数据库迁移建立 application_* 表，不清空旧表。管理员、普通用户、代理资格、等级、预付余额、操作日志和平台配置继续使用。在“历史授权档案”查看原产品、卡密、许可证与版本数量，并下载不含凭证的盘点报告。

旧的激活、验证、卡密发放、实例密钥、离线文件下载和升级接口返回 `410 AUTHORIZATION_V2_REQUIRED`，不能作为新协议的备用入口。旧卡密原文不再导出，旧 JWT 不能换取新 JWT。旧表及备份可能仍含历史加密凭证，只供受控备份与追溯，不作为运行时凭证来源。

如果已有需要保留的试用客户，在页面依次完成：

1. 创建新应用并配置模型、绑定、形态和策略，保存一次性服务端凭证。
2. 核对合同及旧记录，创建对应套餐；使用期限和更新期限分别核对。
3. 建立新销售记录，记录重新签发原因与原客户参考号。不要重复收款；库存/人工签发需有审计原因。
4. 指定原客户账号、预录正确域名/IP，发送一次性安装邀请或新卡密。
5. 以标准接入项目更新产品，客户保留新安装私钥与状态目录。旧版本归档不自动发布到新应用，需验证包和目标后重新上传。
6. 在应用审计核对激活、期限、更新资格和原客户关联，确认后保留旧盘点报告。

不要直接改数据库来绕过套餐或期限校验；复杂旧合同先在测试环境完整确认再签发。没有历史数据的新安装可直接在安装引导后创建应用，无需转换操作。
