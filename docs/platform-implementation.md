# 平台功能实施与验收

按阶段推进，每阶段包含自动化测试、实际服务验证和页面截图。截图中的数据均为隔离环境生成的演示数据。

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 1 | 普通用户、授权归属和隔离、换绑控制、全操作记录 | 已验收 |
| 2 | 应用分组、统一套餐、代理等级与成本、原子流水 | 已验收 |
| 3 | 用户门户完善、管理员归属转移、首页与代理验真 | 已验收 |
| 4 | 可配置盗版检测、告警处置、应用端拦截及解除 | 已验收 |

共同约束：原有使用/更新权限分离规则保持有效；公开查询不授予所有权；用户不能自行转移授权归属；日志不记录明文卡密、密码、访问令牌和私钥。

## 第一阶段

- 独立普通用户账号与用户中心，管理员开户、停用；用户只看自己的应用、续费和按规则换绑。公开查询及已使用卡密均不能认领他人的授权。
- 按应用实际绑定方式设置是否可换、累计次数及冷却时间。原激活接口踢旧绑定、旧解绑接口也使用相同限制，防止绕过；重试不重复扣次数，并发不能超额。
- 授权归属转移默认关闭。管理员必须显式开启、填写原因并核对原归属；普通用户不能转移。
- 全部业务 API 进入操作日志，包含查询、失败、身份、分类、目标及请求号，后台可筛选、分页及导出。日志不可用时拒绝进入业务处理；处理中断保留待核对记录。新用户、换绑、归属等关键变更与业务审计同事务提交。
- 换绑后旧值在线校验立即失效；已签发的离线凭证仍受原离线有效期约束，离线应用应使用短期凭证或联网复核。

验证：后端完整测试、前端类型检查与构建通过；隔离 SQLite 真实服务和浏览器通过；Docker 内置 MySQL 的同一业务验收及重启持久化验证通过。可复跑脚本见 [平台验收说明](../examples/platform-e2e/README.md)。当前会话证据在 `/workspace/artifacts/platform/stage1/`，包括用户授权、冷却期拒绝、跨用户拒绝、后台用户及分类拒绝日志截图，以及 `report.json`。

## 第二阶段

- 后台“套餐与结算”管理应用分组、统一套餐、代理等级、等级价格、代理专属价格、套餐授权及预付余额。按分组授予当前已上架的套餐，之后新增的应用和套餐不会自动扩权。
- 套餐规格固定，时长变化必须新建套餐；可停用和调整基础成本。代理只有已授予且可用的套餐，不能通过旧接口自行指定其他时长、应用或价格。价格按代理专属价、等级价、套餐基础价依次取值。
- 金额全部以人民币分的整数存储，后台手工登记预付余额或扣减并填写原因。发卡按实际成本结算；需要原张数额度的应用可显式启用“双重额度”限制。原张数额度保留，不自动转换为金额。
- 代理发卡必须提交 `package_id`、`quantity`、`request_id` 和 `expected_unit_cost`。服务端核验报价，使用代理及应用行锁防止并发透支。卡密、批次、扣款、可选张数额度、成本快照流水、请求去重及业务审计在同一事务提交；相同请求重试返回原批次，参数变化拒绝。
- 普通代理不能创建套餐、改价格或看其他代理的余额、授权和流水。管理员代生成也走同一结算逻辑。
- 套餐使用现有应用的使用/更新规则：更新天数为 0 时跟随卡密时长，固定更新天数则按应用配置；使用永久不代表更新永久。

升级注意：旧代理发卡集成必须迁移到上述套餐参数，管理员需建立并授予套餐，再登记预付余额。不会把旧允许天数或缺失价格自动视作免费发卡权限；基础价为 0 只能来自管理员明确建立的零价套餐。

验证：后端完整测试与 `go vet`、前端构建通过；真实浏览器完成分组授权、余额登记、等级价发卡及流水展示；SQLite 与 Docker/MySQL 验证重试去重、并发透支拒绝、卡密激活、撤销套餐授权及拒绝日志，容器重启后核对余额、流水、批次和撤销状态。事务审计失败注入测试验证整笔回滚。当前截图及报告在 `/workspace/artifacts/platform/stage2/`。

## 第三阶段

- 首页提供授权验真、代理验真入口及普通用户中心入口。代理验真使用公开代理编号，支持按应用代码核对；仅返回当前登记状态和实际已授予套餐对应的可售应用。
- 代理暂停、停用或套餐撤销后，公开查询立即反映权限变化；不公开登录代码、联系方式、代理账号、价格、余额、内部 ID 和应用密钥。管理员和代理工作台展示可对外提供的公开编号。
- 用户中心分别显示应用使用与更新是否可用、到期时间和下次换绑时间。
- 验证管理员在显式开启转移后填写原因执行归属变更，原用户即失去管理权限，新用户获得授权信息；绑定、使用及更新权益不因归属变更而重置，过时归属请求被拒绝。

验证：后端、前端、真实浏览器和 Docker/MySQL 业务检查通过。公开代理正常及暂停状态、管理员归属转移和新用户授权中心截图及报告在 `/workspace/artifacts/platform/stage3/`。

## 第四阶段

- 按应用启用安全策略：服务端绑定异常、客户端升级包完整性报告、确认后的建议动作、纯文字提示和联系链接。默认关闭。待核实线索只记录，不自动封禁，客户端报告明确标记未经独立证实。
- 管理员逐条核实并填写原因，可选择观察、只禁更新、禁止使用和更新或应用端拦截页；处置和审计同事务保存，可解除并保留历史。
- Node.js SDK 支持校验失败报告、在线安全决定及 Web 入口中间件。真实网站接入后，确认的拦截返回带处置编号的 403 页面；只禁更新时仍可访问网站。普通过期显示授权提示，连接故障显示 503，均不冒充盗版结论。
- 授权用户查看自己的记录并提交申诉，不能确认或解除处置。管理员排除误报后恢复在线使用与更新，相关申诉关闭。
- 服务端验证、心跳、原卡激活、续费、更新检查及下载受已确认处置约束；安全策略不能授予已过期的更新权限。管理员建立套餐与改价必须显式提供成本字段，缺失值不会变为免费套餐。

验证：后端完整测试、`go vet`、前端构建、三个 SDK 测试通过；Node.js 16 项测试含 HTML 转义、联系链接限制、只禁更新、网络与过期区分及可选完整性报告。订阅和永久使用两套真实升级回归各 6 项通过。真实浏览器完成安全配置、升级包篡改检测、确认处置、网站拦截、用户申诉和解除恢复。Docker/MySQL 验证四个阶段，并在重启后核对安全策略、已解除记录与关闭申诉。截图及报告在 `/workspace/artifacts/platform/stage4/`。

拦截依赖应用接入校验及中间件；完全移除校验的副本不能保证远程拦截，离线缓存需再次联网或失效后获知新处置。接入与完整边界见 [安全接入说明](security-integration.md)。
