# 应用安全检测与拦截接入

平台保存检测线索、管理员核实结论和处置策略；应用负责在访问入口执行决定。每个应用的安全策略默认关闭，可分别启用绑定异常检测和客户端升级包完整性报告。

## 检测与核实

- 服务端验证返回绑定不匹配时，可生成待核实线索。同一授权、同类信号累计次数，避免重复记录；绑定配置错误也可能触发，不能直接认定盗版。
- Node.js SDK 可在升级包签名清单已验证、下载内容 SHA-256 不符时提交完整性报告。服务端比对自己保存的已发布版本哈希，校验报告对应的应用、授权和绑定。
- 客户端报告标记为未经独立证实；报告内容可被客户端伪造，因此观察记录不会自动封禁。管理员核对部署、版本和购买凭证后才能确认并选择动作，填写原因并留下审计。
- 普通到期、授权吊销、网络故障分别遵循原授权逻辑，不会自动创建盗版记录。

已确认记录可选：仅观察、只禁止更新、禁止使用与更新、应用端拦截页。应用策略中的“建议动作”供人工确认时使用，启用策略本身不会把待核实记录变成封禁。解除记录后在线使用与下载恢复，相关用户申诉同步关闭；历史记录仍保留。关闭应用安全策略会暂停该应用的检测与已确认处置。

管理员在“盗版处置 → 应用安全策略”选择应用，填写“打击盗版公告”，例如“站点未授权，联系 QQ 531023977”。公告支持多行纯文字，最多 1000 字节；保存后显示在固定拦截页的公告区域。“预览拦截页”使用与真实页面相同的模板，可实时检查内容和布局；可选联系链接单独配置。公告中的 HTML 会作为文字显示，电脑和手机使用相同的响应式版式。

## Node.js 网站接入

```js
import { LicenseClient, enforceWebLicense } from '@yunnuo/license-sdk';

const client = new LicenseClient({
  baseUrl: 'https://license.example.com',
  appKey: process.env.LICENSE_APP_KEY,
  reportIntegrityFailures: true,
});

// 在自己的 HTTP 请求处理函数中，在输出应用内容之前执行：
if (await enforceWebLicense(client, binding, response)) return;
// 通过后继续处理应用请求。
```

`binding` 包含 `license_no`、`bind_mode`、`bind_value`。应从应用自己的可信部署配置及实际部署标识生成，使用域名授权时核对真实访问域名；不要让外部用户传入任意授权号和绑定值来决定自己的访问权限。生产环境使用 HTTPS，并固定升级包验签公钥及产品 ID。

中间件在线请求 `/v1/security/decision`。仅禁止更新时继续提供应用页面；已确认的拦截返回 HTTP 403、处置编号及管理员配置的纯文字提示和联系链接。HTML 转义、联系链接协议限制、CSP 和禁止缓存由 SDK 处理。普通授权不可用显示授权提示；服务故障显示 HTTP 503 服务异常提示，不显示盗版结论。

升级检查和下载仍使用原来的 `/v1/updates/...`，在服务端同时校验授权期限、绑定及已确认处置。安全策略只能增加限制，不能授予到期后的更新权限。只禁更新的用户仍然可以使用应用。`securityDecision` 与 `reportIntegrity` 也可直接调用；其他语言可按相同 JSON API 接入。

授权用户在用户中心查看自己的安全记录并提交申诉；用户不能自行解除处置，管理员在后台核实后执行。普通用户不能读取他人的线索或内部证据，也不能确认处置。

## 能力边界

中间件必须放在应用实际访问入口，保护需要授权的页面和 API。升级包哈希报告检测分发包异常，不等于任意运行文件都具备防篡改能力。应用完全移除联网校验、拦截代码或检测上报后，平台无法保证远程拦截这份修改后的副本。已签发的离线缓存凭证也需到其有效期或再次联网后才能获知新处置，要求及时撤销的应用应缩短离线有效期或强制在线验证。

可复现的真实网站见 `examples/security-demo/server.mjs`，完整篡改包、确认处置、拦截、申诉与解除验证见 `examples/platform-e2e/test_stage4.py`。
